# AI質問機能 要件定義書（docs/ai/requirements.md）

- 根拠：docs/ai/request.md（要望書と授業の共通条件）
- 作業ブランチ：feature/ai-app
- 作成日：2026-11-25

## 1 背景・目的・利用者・対象範囲

### 1.1 目的
既存の Express＋TypeScript サイト（TOP・TODO）に、利用者が質問を送るとサーバー経由で Gemini API が回答し、質問と回答を DB に保存して履歴として見られる「AI質問アプリ」を追加する。APIキーをブラウザに渡さないこと、失敗時に安全に復帰すること、公開環境で勝手に使われないことを重視する。

### 1.2 利用者
授業の受講者本人と講師（デモ・確認用）。認証は行わない。

### 1.3 対象範囲（標準課題）
- 画面 /ai：質問入力、回答と履歴の表示
- API：POST /api/ai/ask（質問）、GET /api/ai/history（履歴）
- DB：ai_qa_logs への質問・回答・日時の保存と取得
- 公開停止：環境変数 AI_DEMO_ENABLED による API の停止
- 既存の /、/api/db-check、/todo、/todo-v2、/api/v1/todos、/api/v2/todos を維持

### 1.4 対象外（発展課題・今回は作らない）
ログイン、会話の記憶（過去履歴を AI に送る）、Markdown 表示、ストリーミング表示、履歴の削除・検索、利用者ごとの履歴分離。

## 2 機能要件（REQ-AI-Fxxx）

| ID | 要件 | 受入条件 |
| --- | --- | --- |
| REQ-AI-F001 | /ai で質問フォーム、送信ボタン、状態表示、履歴一覧を持つ画面を表示する。TOP から /ai へ移動できる | /ai を開くとフォームと履歴欄が表示される。TOP のリンクから /ai に移動できる |
| REQ-AI-F002 | 質問をページ遷移なしでサーバーへ送り、サーバーが Gemini API を呼んで回答を得る。今回の質問だけを送り、過去履歴は送らない | 送信後に画面遷移せず回答が表示される。AI への送信内容に過去の質問が含まれない |
| REQ-AI-F003 | AI 回答の取得と DB 保存の両方が完了したときだけ成功（201）とし、保存した 1 件を返す | 201 の応答の内容と DB の行が一致する。保存に失敗した場合は 201 を返さない |
| REQ-AI-F004 | 履歴を最新 20 件、作成日時の降順（同日時は ID の降順）で返し、画面に表示する | 21 件以上あっても 20 件だけ、新しい順に表示される。再読み込みで同じ履歴が表示される |
| REQ-AI-F005 | 履歴 0 件は正常として 200 と空配列を返し、画面に「履歴がありません」と表示する。取得失敗とは区別する | 0 件の DB で GET が 200・items: []。DB 障害時は 0 件表示にならず、取得失敗の案内が出る |
| REQ-AI-F006 | 入力が不正なとき（空白だけ、2,000 コードポイント超、文字列以外、JSON 不正、16KiB 超）は AI を呼ばず、保存もしない | 各ケースで 4xx の安全なエラーが返り、AI 呼出し・DB 保存が行われない |
| REQ-AI-F007 | AI 失敗（通信エラー、待機期限切れ、空回答、利用枠超過など）と DB 保存失敗を、固定のコードと文言で返し、生の例外を返さない | 502／504／500 等の固定コードが返り、応答に例外文・SQL・キーが含まれない。サーバーは停止しない |
| REQ-AI-F008 | 送信中はボタンを無効化して重複送信を防ぎ、成功時だけ質問欄を空にする。失敗時は質問を残し、安全な案内を表示して操作可能に戻す | 待機中の連打で 2 件送信されない。失敗後も質問が残り、再度送信できる |
| REQ-AI-F009 | ブラウザも SDK も自動で再送しない。再送は利用者が送信ボタンを押したときだけ行う | 失敗時に自動で同じ質問が送られない。SDK の再試行回数が 1（初回のみ）に設定されている |
| REQ-AI-F010 | AI_DEMO_ENABLED が "true" のときだけ質問・履歴 API を動かし、それ以外（未設定・false）は両 API が 503／DEMO_DISABLED を返す。TOP・TODO・静的画面は止めない | false で POST・GET とも 503／DEMO_DISABLED、AI・DB は呼ばれない。/、/todo は動く |

## 3 非機能要件（REQ-AI-Nxxx）

| ID | 要件 | 受入条件 |
| --- | --- | --- |
| REQ-AI-N001 | 既存 TODO と同様に Router／Controller／Service／Model に責務を分け、src/apps/ai/ に置く | ファイル構成が設計書と一致する |
| REQ-AI-N002 | GEMINI_API_KEY・DATABASE_URL はサーバーの環境変数だけで扱い、コード・Git・ブラウザ・ログ・応答に出さない | Sources・Network・Git 差分にキーや接続情報がない。ブラウザから Gemini へ直接通信しない |
| REQ-AI-N003 | 既存の /、/api/db-check、/todo、/todo-v2、両 TODO API の動作を変えない | 既存機能の主要操作が従来どおり動く |
| REQ-AI-N004 | 質問・回答・エラー文は HTML として描画せず文字列として表示する | `<img src=x onerror=alert(1)>` のような質問・回答が実行されず文字として表示される |
| REQ-AI-N005 | SQL はプレースホルダを使う | Model の SQL に文字列連結した値がない |
| REQ-AI-N006 | AI の待機は 30 秒、ブラウザの待機は 45 秒を上限とし、期限切れは失敗として扱う（参考設定、実環境で確認） | 期限切れでも UI が操作可能に戻る |
| REQ-AI-N007 | エラー時は問い合わせ ID を応答とサーバーログに出し、ログには質問本文やキーを出さない | 応答の requestId でログの該当行を探せる。ログに質問本文・キーがない |

## 4 データ要件（REQ-AI-Dxxx）

| ID | 要件 | 受入条件 |
| --- | --- | --- |
| REQ-AI-D001 | テーブル ai_qa_logs に id、prompt（質問）、response_text（回答）、created_at を保存する。質問は 1〜2,000 文字、回答は空不可 | SQL の制約と一致し、制約違反の行が保存されない |
| REQ-AI-D002 | 履歴の並びに合わせ、created_at DESC, id DESC のインデックスを設ける | SQL にインデックスがある |
| REQ-AI-D003 | API では DB 列を id、prompt、response、createdAt に変換して返す | 応答のキーが camelCase で、response_text 等の列名が出ない |
| REQ-AI-D004 | 既存テーブル（todo_tasks、v2_todo_tasks）を変更・削除しない | 030 の SQL に既存テーブルへの操作がない |
