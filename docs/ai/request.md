# AI質問機能 追加要望書（docs/ai/request.md）

> 配布元：講師リポジトリ hanari-teacher/Ai-drive-Project2026 の docs/ai/request.md（2026-11-25 取得）。本文は配布どおりの内容を転記し、末尾に授業で確定した共通条件と変更記録を追記した。

## 1. 概要

本プロジェクト（Express / TypeScript 製の既存Webアプリケーション）に、ユーザーからの質問を受け付け、AI（LLM）が回答を生成・返却する「AI質問機能」を追加する。既存のTODOアプリと同様のレイヤー構造を踏襲し、保守性と拡張性の高い設計で実装を行う。

## 2. 背景・目的

- 目的：ユーザーがアプリケーション上で疑問点や質問を入力した際、AIが迅速に適切な回答を返す仕組みを提供し、アプリの利便性を向上させる。
- 対象ユーザー：本アプリを利用する一般ユーザーおよび管理者。

## 3. 要件定義（要望）

### 3.1 機能要件
1. AI質問画面（UI）の提供：質問の入力フォームと、AIからの回答を表示するエリアを持つ画面（またはTOP・TODO画面に統合するセクション）を提供する。
2. 質問送信とAI応答処理：入力した質問テキストをバックエンド（Expressサーバー）に送信し、サーバー側で外部AI APIを呼び出して回答を取得し、フロントエンドに返却する。
3. エラーハンドリング：API通信エラーや入力値不正（空文字など）が発生した場合に、ユーザーフレンドリーなエラーメッセージを画面に表示する。サーバーがクラッシュしないよう、適切な例外処理とグローバルエラーハンドラーへの連携を行う。

### 3.2 非機能要件
- アーキテクチャの踏襲：既存の TODO アプリ（src/apps/todo/）の Router / Controller / Model・Service の分離に倣い、src/apps/ai/ を新設する。
- セキュリティ・機密情報管理：AIのAPIキー等の機密情報はソースコードに直書きせず、dotenv を利用して環境変数から読み込む。
- 既存機能への影響ゼロ：既存のTODO機能、ルーティング、DB接続、404ハンドリング、エラーハンドリングを破壊しない。

## 4. 実装・配置スコープ案（要望書時点）
- src/apps/ai/aiRouter.ts、aiController.ts、aiService.ts
- views/ai/index.ejs、public/ai/ai.js
- index.ts にルーターを追加
- AI SDK、環境変数 AI_API_KEY（または採用するAIのキー名）

## 5. 授業で確定した共通条件（授業テキスト 5.2）

| 項目 | 共通条件 |
| --- | --- |
| 質問 | 前後空白除去後 1〜2,000 Unicodeコードポイント |
| JSON本文 | 受信上限 16KiB（16,384バイト） |
| 履歴 | 最新20件、作成日時の降順、同日時ならIDの降順 |
| 保存成功 | AI回答の取得とDB保存を完了してから成功応答 |
| 会話文脈 | 今回の質問だけを送る。過去履歴は送らない |
| 再送 | ブラウザとSDKの自動再試行をしない |
| 公開 | ローカルまたは保護済みPreviewでデモ。Productionは標準ではAPI停止 |
| 待機 | 参考設定として AI 30秒、ブラウザ 45秒 |
| 利用AI | Gemini API（@google/genai）、モデル gemini-3.5-flash-lite（授業テキスト指定） |
